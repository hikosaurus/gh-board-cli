# Git Rules

## Branch

- `main` : 
  - デフォルトブランチ. ここからdevelopブランチを派生/マージする.
  - **直接コミットしないこと**
- `develop` :
  - 開発の本ブランチ. featureブランチを派生/マージする.
- `feature/*` : 
  - 機能開発ブランチ. 
  - GithubIssueと紐づく場合は `feature/{issue_number}-{対応内容を簡潔に要約}` と命名する

## Commit

- 変更内容の関心事が複数ある場合、別のコミットに分けること.
- コミットメッセージは次の形式に従うこと.
  ```
  {gitmoji} {コミット種別} {変更内容を完結に1行で記述}
  
  {Description}
  ```
- コミット種別
  - `fix`     ：バグ修正
  - `hotfix`  ：クリティカルなバグ修正
  - `add`     ：新規（ファイル）機能追加
  - `update`  ：機能修正（バグではない）
  - `change`  ：仕様変更
  - `clean`   ：整理（リファクタリング等）
  - `disable` ：無効化（コメントアウト等）
  - `remove`  ：削除（ファイル）
  - `upgrade` ：バージョンアップ
  - `revert`  ：変更取り消し
- Description
  - 変更内容を箇条書きで記述する. 各項目は、改行せず1行で.
  - バグ修正コミットの場合は、原因/対処のセクションに分けて記述.
